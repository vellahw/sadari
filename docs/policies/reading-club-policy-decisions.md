# 독서 모임 정책 결정 항목

## 개요

- 목적: 독서 모임의 확정 정책과 후속 출시 범위를 구분하여 구현·화면 설계의 단일 기준으로 관리합니다.
- 적용 대상: 독서 모임을 개설·탐색·가입·운영·퇴장하거나 회차, 독후감, 다음 도서, 채팅 및 모임장 선거를 이용하는 회원입니다.
- 기준일: 2026년 8월 31일입니다.
- 구현 상태: 공개 모임 탐색·생성·가입, 모임원 관리, 공동 독서 회차, 종료 결과, 회차 독후감과 이전 독서 기록 화면·API를 제공합니다. 후속 출시 항목은 각 정책 표와 구현 상태 절에 별도로 표시합니다.
- 설계 기준: [독서 모임 기능 설계](../architecture/reading-club-design.md)를 따르며 사용자 차단 출시 후의 공동 모임 예외는 [사용자 차단 기능 설계](../architecture/user-blocking-design.md)를 함께 적용합니다.

## 상태 기준

| 상태 | 의미 |
| --- | --- |
| `확정` | 사용자가 요구사항으로 명시하여 구현 기준으로 사용할 수 있습니다. |
| `후속 출시` | 1차 출시 범위에서 제외되었으며 해당 기능을 설계할 때 별도 정책 확정이 필요합니다. |

| 정책 결정 | 관심분야 분류 | 단일 공통코드 공지사항 카테고리 분류 아래에 대분류를 1뎁스 분류값로 만들고 실제 관심분야를 대분류의 자식 분류값로 사용합니다. 회원 독서 관심분야와 독서 모임 카테고리에는 선택한 세부 관련 업무 데이터 항목 하위 관심분야 분류값만 저장하고 대분류나 공통코드 그룹은 중복 저장하지 않습니다. | 확정 |
| 정책 결정 | 복수 모임 | 한 회원은 여러 모임을 개설하고 여러 모임에 참여할 수 있습니다. | 확정 |
| 정책 결정 | 다음 도서 | 모임원은 다음 도서를 추천할 수 있고 선정된 도서로 다음 회차를 진행합니다. | 확정 |
| 정책 결정 | 채팅 | 활성 모임원끼리 모임 채팅을 사용할 수 있습니다. | 확정 |
| 정책 결정 | 모임장 승계 | 모임장이 자발적으로 승계를 요청하면 특정 회원을 직접 후임으로 지정하지 않고 모임장 선거를 시작합니다. | 확정 |
| 정책 결정 | 관심분야 선택 개수 | 회원은 활성 세부 관심분야를 개수 제한 없이 선택할 수 있습니다. | 확정 |
| 정책 결정 | 모임 찾기 관심분야 필수 | 관심분야가 없는 회원은 `모임 찾기`에서 공개 목록을 볼 수 없으며 하나 이상 저장해야 합니다. 선택을 취소하거나 건너뛰어 일반 목록으로 진입할 수 없습니다. | 확정 |
| 정책 결정 | 관심분야 코드 구조 | 옵션코드를 사용하지 않고 공통코드 세부 항목의 상위 분류값 자기참조 계층으로 확장합니다. | 확정 |
| 정책 결정 | 가입 질문·답변 보존 | 모임 가입 질문의 현재 질문 양식은 모임이 존재하는 동안 유지합니다. 승인형 모임 가입 신청의 신청 답변은 승인 또는 거절 처리와 같은 트랜잭션에서 즉시 삭제합니다. | 확정 |
| 정책 결정 | 회차 자동 참여 | 도서와 목표 기간 확정 시 별도의 참여 선택 없이 그 시점의 모든 활성 모임원을 회차 참여자로 고정합니다. | 확정 |
| 정책 결정 | 자동 생성 독후감 상태 | 자동 생성한 개인 독후감의 초기 상태는 `읽는 중`입니다. | 확정 |
| 정책 결정 | 자동 생성 독후감 직접 삭제 | 활성 모임원이 진행 중인 회차의 자동 생성 독후감을 직접 삭제하면 해당 회차는 중도하차로 처리하고 참여 기록은 목표 미달성으로 보존합니다. | 확정 |
| 정책 결정 | 목표 종료 후 개인 기록 | 목표 기간 안에 완료하지 못한 개인 독후감은 `읽는 중` 상태로 유지하며 이후에도 실제 독서 기간과 독후감을 계속 작성·수정할 수 있습니다. | 확정 |
| 정책 결정 | 회차 목표 달성 판정 | 목표 종료 시각까지 개인 독후감이 `완독`이 된 회원만 해당 회차의 목표 달성자로 확정합니다. 마감 후 개인 독후감을 완료해도 종료된 회차 결과는 바뀌지 않습니다. | 확정 |
| 정책 결정 | 채팅 신고·차단 출시 | 채팅 신고와 사용자 차단은 1차 독서 모임 출시에 포함하지 않고 공통 신고·차단 기능에서 후속 출시합니다. | 확정 |
| 정책 결정 | 사이드 메뉴 구조 | 사이드 메뉴는 `독서 모임` 상위 메뉴 아래 `내 모임`, `모임 찾기` 두 하위 메뉴를 둡니다. | 확정 |
| 정책 결정 | 관심분야 적용 범위 | `내 모임`, 받은 초대, 내 가입 신청 및 가입한 모임 상세는 관심분야 없이 이용할 수 있고, 관심분야 필수 조건은 `모임 찾기`와 미가입 공개 모임 상세에만 적용합니다. | 확정 |
| 정책 결정 | 모임장 부재와 승계 | 물리 삭제, 복구 불가능한 영구 이용 제한, 모임장의 자발적 승계 요청, 모임장만 다음 도서를 확정할 수 있는 상태가 시작된 뒤 14일 동안 도서를 확정하지 않은 경우 및 관리자가 같은 수준으로 확정한 사유를 확정 부재로 보고, 확정 후 활성 모임원 투표로 다음 모임장을 선출합니다. 별도 모임장 변경 감사 이력은 두지 않습니다. | 확정 |
| 정책 결정 | 공통 신고·차단 출시 | 독후감, 댓글, 모임, 사용자 및 향후 추가 대상을 포괄하는 신고·차단 기능은 독서 모임과 분리된 공통 도메인으로 후속 출시합니다. | 확정 |
| 정책 결정 | 차단 관계의 공동 모임 | 차단 전부터 존재한 공동 모임과 제3자인 모임장의 초대·수락은 유지하고, 차단 당사자가 모임장인 공간으로의 신규 초대·가입·신청·승인은 제한합니다. | 확정 |
| 정책 결정 | 차단 시 대기 관계 정리 | 차단 당사자 사이의 미수락 직접 초대는 만료하고 당사자 소유 모임의 처리 중 가입 신청은 취소와 동시에 답변을 삭제하며 처리 알림을 생성하지 않습니다. 제3자인 모임장이 발송한 유효 초대는 유지합니다. | 확정 |
| 정책 결정 | 차단 상대의 모임 표시 | 기존 공동 모임에서 차단 상대의 닉네임과 운영 본문은 표시하되 사진은 기본 이미지로 대체하고 공개 프로필 이동과 직접 좋아요·댓글·답글을 제한합니다. | 확정 |
| 정책 결정 | 모임 종속 데이터의 복합키 | 채팅을 제외한 모임 종속 테이블은 기본키와 부모 참조 외래키가 모임 번호로 시작하도록 구성합니다. 자연 관계는 자연 복합키를 사용하고 번호가 필요한 자식 데이터는 부모 범위의 지역 번호를 사용합니다. 회차 참여는 영구 탈퇴 뒤 비식별 보존을 위해 `(모임 번호, 모임별 회차 번호, 모임 회차별 참여 번호)`를 기본키로 사용합니다. | 확정 |
| 정책 결정 | 모임별 번호 발급 | 가입 신청, 회차, 회차 참여, 도서 선정·추천, 퇴장 이력, 모임장 선거, 공통 투표 및 관리자 조치 이력의 지역 번호는 각 대상 테이블의 `INSERT` 문 안에서 부모 범위의 `MAX(번호) + 1`로 발급합니다. 초대는 `모임 회원 및 초대 예약석(모임 번호, 사용자 번호)`로 식별하므로 별도 번호를 발급하지 않습니다. 회차 참여의 모임 회차별 참여 번호는 동일 모임 번호, 모임별 회차 번호 범위에서 발급하며 별도 키 발급 테이블은 두지 않습니다. | 확정 |
| 정책 결정 | 채팅 키 예외 | 모임 채팅의 채팅 메시지 번호는 전역 `AUTO_INCREMENT` 단일 기본키를 사용하고 모임 번호는 외래키와 조회 인덱스로 관리합니다. 채팅에는 `MAX + 1`을 사용하지 않습니다. | 확정 |
| 정책 결정 | 공통 투표 모델 | 다음 도서 선정과 모임장 선거의 업무 마스터는 분리해 유지하고 투표 이벤트·선택지·유권자·투표용지는 모임 투표, 모임 투표 선택지, 모임 투표 참여 기록, 모임 투표 자격로 공통 관리합니다. | 확정 |
| 정책 결정 | 공통 투표 선택지 키 | 모임 투표 선택지는 별도 선택지 번호 없이 `(모임 번호, 투표 번호, 대상 번호)`를 기본키로 사용합니다. 대상 번호는 `BOOK` 투표에서 도서 번호, 모임장 투표에서 후보 사용자 번호를 의미합니다. | 확정 |
| 정책 결정 | 공통 투표 유권자 | 도서·모임장 투표를 시작할 때 활성 모임원을 모임 투표 참여 기록에 고정하고 같은 투표·유권자의 투표용지는 모임 투표 자격 한 행만 유지합니다. | 확정 |

## 확정 정책의 적용 해석

### 독후감 공개 범위

- `독후감의 공개 여부 = 'N'`은 일반 공개 목록과 비회원 열람을 차단합니다.
- 독서 모임 회차 참여의 독후감 번호로 연결된 독후감은 공동 목표 기간 종료 후 별도의 모임원 권한으로 열람합니다.
- 모임 공개를 위해 작성자의 공개 여부를 `Y`로 자동 변경하지 않습니다.
- 공개 모임이라는 이유만으로 비회원에게 모임 독후감을 공개하지 않습니다.
- 작성자 본인은 목표 기간 종료 전에도 자신의 독후감을 볼 수 있습니다.
- 별도 제출본 테이블을 만들지 않으며 본문, 상태, 평점 및 실제 독서 기간은 독후
- 감을 단일 기준으로 사용합니다.

### 온보딩과 관심분야

- 웰컴 화면 완료 여부와 관심분야 저장 여부는 서로 독립적으로 처리합니다.
- 회원이 관심분야를 선택하지 않거나 저장에 실패해도 닉네임 등 웰컴 완료 조건을 충족하면 `온보딩 완료 여부 = 'Y'`로 처리합니다.
- 관심분야 저장 실패는 경고로 안내하고 서비스 전체 진입을 막지 않습니다.
- 관심분야가 없는 회원도 `내 모임`, 받은 초대, 내 가입 신청 및 가입한 모임 상세는 이용할 수 있습니다.
- `모임 찾기`와 미가입 공개 모임 상세에 진입하려면 활성 공지사항 카테고리 분류 아래의 활성 대분류 및 관심분야로 구성된 유효한 관심분야를 하나 이상 저장해야 합니다.
- 관심분야가 없으면 필수 선택 화면을 표시하며, 선택을 취소하거나 건너뛰어 일반 공개 모임 목록으로 진입할 수 없습니다.
- 관심분야 저장에 실패하거나 선택값이 없으면 선택 화면에 머물고 공개 모임 목록을 조회하지 않습니다.
- 회원 독서 관심분야에는 사용자 번호, 관련 업무 데이터 항목 하위 관심분야 분류값, 등록 일시를 저장합니다.
- 독서 모임 카테고리에는 모임별로 모임 번호, 관련 업무 데이터 항목 하위 관심분야 분류값, 정렬 순서, 등록 일시를 저장합니다.
- 모임은 서로 다른 유효 카테고리 조합을 최소 1개, 최대 3개까지 선택할 수 있고 `정렬 순서 = 1`인 조합을 대표 카테고리로 사용합니다.
- Service는 회원과 모임의 관련 업무 데이터 항목 하위 관심분야 분류값이 활성 공지사항 카테고리 분류 대분류의 활성 하위 코드인지 검증합니다.
- 공지사항 카테고리 분류 최상위 분류값의 공통코드 세부 항목의 분류값 이름은 대분류 표시명, 그 자식 분류값의 분류값 이름은 관심분야 표시명으로 사용합니다.
- 회원은 대분류와 세부 카테고리를 한 조합으로 선택하며 같은 대분류의 여러 세부 카테고리도 각각 한 행으로 저장합니다.
- 회원의 선택 개수에는 업무상 상한을 두지 않습니다. 다만 중복 조합은 허용하지 않고 요청 본문의 일반적인 크기·개수 방어 제한은 별도로 적용합니다.
- 관심분야와 모임 카테고리의 정확 일치는 양쪽 관련 업무 데이터 항목 하위 관심분야 분류값이 같은 경우로 판정합니다. 대분류만 같고 분류값이 다르면 정확 일치로 처리하지 않습니다.
- 공개 모임 추천은 회원 관심분야와 정확히 일치한 모임 카테고리 조합 수를 모임별로 중복 없이 집계하고 일치 개수가 많은 모임을 먼저 노출합니다.
- 세부 카테고리를 늘릴 때는 공지사항 카테고리 분류의 해당 대분류 코드를 상위 분류값로 지정한 공통코드 세부 항목 행을 추가합니다.
- 독서 관심분야는 공지사항에서 사용하는 카테고리 분류를 재사용하며 별도의 중복 분류 그룹을 유지하지 않습니다.

### 모임 생성 독후감 식별

- 독서 모임 회차 참여의 독후감 번호가 독후감 번호를 참조합니다.
- 독서 모임 회차 참여의 독후감 번호에는 고유 제약을 두어 하나의 독후감이 여러 회차에 연결되지 않게 합니다.
- 조인 결과가 있으면 모임에서 자동 생성된 독후감이고, 없으면 일반 개인 독후감으로 판단합니다.
- 개인 책장과 모임 화면은 같은 독후감을 조회하므로 수정 내용이 양쪽에 동일하게 반영됩니다.
- 진행 회차에 연결된 독후감은 관계가 유지되는 동안 임의 삭제를 제한합니다.

### 목표 기간과 실제 기간

- 회차의 목표 시작일과 목표 종료일은 모든 참여자가 공유하는 계획입니다.
- 도서와 목표 기간을 확정하는 시점의 모든 활성 모임원을 별도 응답 없이 회차 참여자로 고정합니다.
- 회차 확정 시 모든 참여자의 개인 독후감을 `읽는 중` 상태로 생성하고 독서 시작일, 독서 종료일 또는 목표 종료일에는 우선 공동 목표 기간을 기록합니다.
- 회원이 실제 독서 기간을 저장하면 연결된 개인 독후감의 기간을 갱신합니다.
- 모임 화면은 연결된 독후감 번호로 같은 기간을 조회하며 별도 기간 값을 독립적으로 수정하지 않습니다.
- 회차의 공동 목표 기간은 개인 실제 기간으로 덮어쓰지 않습니다.
- 목표 종료 시각까지 `완독` 전환이 확인된 참여자는 회차 목표 달성, 나머지는 목표 미달성으로 고정합니다.
- 목표 기간이 시작된 뒤 종료되기 전까지 활성 계정이면서 해당 모임의 활성 모임장인 회원은 활성 참여자 전원이 `완독`이면 회차를 조기 마감할 수 있습니다. 서버는 모임장 권한, 목표 기간과 전원 완독 상태를 같은 트랜잭션에서 다시 확인하고 마감 시점의 목표 달성 결과를 고정합니다.
- 조기 마감된 회차는 일반 완료 회차와 동일하게 다시 열지 않으며, 마감 시점의 모든 활성 모임원에게 해당 회차의 미확인 목표 결과를 생성합니다.
- 활성 모임원은 새 회차 진행 여부와 관계없이 모임 상세 진입 즉시 가장 최근의 미확인 목표 결과를 확인합니다. 모임장 선거가 함께 있으면 목표 결과를 먼저 표시하고 닫은 뒤 선거 화면을 표시합니다.
- 목표 미달성자의 개인 독후감은 `읽는 중` 상태와 작성 중인 내용을 그대로 유지합니다. 마감 후 `완독`으로 바뀌어도 개인 기록만 갱신하고 이미 끝난 회차의 목표 결과는 다시 계산하지 않습니다.
- 회차 화면의 목표 요약에는 전체 참여 인원, 목표 달성 인원 및 목표 달성자 목록만 표시합니다. 미달성자 명단이나 참여·불참 상태는 표시하지 않습니다.
- 현재 독서 목표 현황의 전체 인원은 독서 모임 회차 참여에 고정된 참여자 중 `사용자 계정 상태 = '활성'`이고 `모임 회원 및 초대 예약석의 모임원 또는 초대 상태 = '활성'`인 회원만 집계합니다.
- 진행 중인 회차의 목표 달성 인원은 같은 활성 참여자 범위에서 연결된 `독후감의 독서 상태 코드 = '완독'`인 회원을 실시간 집계합니다. 마감된 과거 회차는 확정된 `독서 모임 회차 참여의 회차 목표 달성 여부 = 'Y'`를 사용하며 개인 독후감의 이후 상태로 결과를 다시 계산하지 않습니다.
- `비활성화` 또는 영구 탈퇴 대기 회원은 목표 달성 인원과 전체 인원에서 제외합니다. 계정 제한 전환 시 비식별화된 기존 회차 참여 관계는 `활성` 복귀 후 자동 복원하지 않습니다.

### 미등록 도서 처리

- 회차 확정 서비스가 도서 마스터의 도서를 한 번만 확보합니다.
- 도서가 이미 있으면 기존 도서 번호를 사용합니다.
- 도서가 없으면 ISBN 고유 제약을 이용해 한 번만 멱등 등록하고 확정된 도서 번호를 모든 참여자의 독후감에 사용합니다.
- 참여자별 독후감 저장 과정에서는 도서 마스터 등록을 반복하지 않습니다.
- 도서 확보에 실패하면 회차와 참여자 독후감을 일부만 남기지 않고 전체 실패 처리합니다.

### 공개 모임 가입

- `OPEN`은 서버가 정원과 중복 가입을 확인한 뒤 즉시 가입합니다.
- 승인형은 모임장이 설정한 현재 질문 전체에 신청자가 답해야 신청할 수 있고 모임장이 질문별 답변을 확인한 뒤 승인해야 가입됩니다.
- 화면에 여석이 표시되어도 즉시 가입과 신청 승인 시점에 서버가 일반 가입 가능 좌석을 다시 계산합니다.
- 비회원과 승인 대기 회원은 채팅과 모임 독후감을 열람할 수 없습니다.
- 공개 모임장도 맞팔 회원을 직접 초대할 수 있습니다.
- 초대 대상은 모임 공개 여부와 가입 방식에 관계없이 맞팔 회원으로 제한합니다.

### 승인 가입 질문과 답변

- 모임 가입 질문은 모임 번호를 기본키로 사용하며 승인형 모임당 한 행만 저장합니다.
- 한 행에는 첫 번째부터 다섯 번째까지의 가입 질문까지 최대 5개의 자유 형식 질문을 저장합니다.
- 질문 유형, 선택지 및 정렬 순서 컬럼은 두지 않습니다.
- 모임장이 복수 선택 형태를 원하면 질문 본문에 번호와 선택지를 직접 작성하고 신청자는 장문형 답변에 선택 번호를 작성합니다.
- 첫 번째 질문은 필수이고 사용하지 않는 후속 질문은 Null로 저장합니다.
- 신청자는 값이 있는 모든 질문에 답해야 합니다.
- 신청 시점의 질문 1~5와 답변 1~5는 승인형 모임 가입 신청 한 행에 함께 저장합니다.
- 질문이 변경되어도 이미 제출된 신청의 질문 사본과 답변은 변경하지 않습니다.
- 모임 가입 질문은 가입 방식이 바뀌거나 모집이 일시 중지되어도 모임이 물리 삭제되기 전에는 삭제하지 않습니다. 사용하지 않는 동안에는 화면 노출과 신규 신청에만 적용하지 않습니다.
- `대기` 동안에는 모임장이 심사할 수 있도록 신청 답변을 유지합니다.
- 승인 또는 거절 시 상태·처리자·처리 일시 갱신과 첫 번째부터 다섯 번째까지의 가입 답변 삭제를 한 트랜잭션으로 처리합니다. 답변 삭제에 실패하면 승인·거절도 확정하지 않습니다.
- 처리된 신청 내역에는 신청 상태와 처리 일시를 남기되 답변 본문은 다시 조회할 수 없습니다. 신청 당시 질문 사본은 신청 이력에 남고 현재 사용 질문은 항상 모임 가입 질문에서 조회합니다.
- 모임장이 직접 보낸 맞팔 초대는 가입 질문과 승인 절차를 생략하고 발송 시점부터 3일 동안 좌석을 예약하며, 초대 대상자에게 `FOLLOW` 상황의 독서모임 초대 템플릿 알림을 발송합니다.
- 모임장이 가입 신청을 승인하거나 거절하면 활성 신청자에게 처리 결과 템플릿 알림을 발송합니다. 모임명을 치환하고 모임을 이동 대상으로 저장하며, 알림 저장에 실패하면 승인·거절과 답변 삭제를 함께 롤백합니다.

### 초대 예약 좌석 확정안

초대 수락 시점에 일반 정원을 다시 경쟁하게 하면 유효한 초대를 수락하고도 가입하지 못할 수 있습니다. 이를 막기 위해 초대 발송 시점부터 3일 동안 좌석을 예약합니다.

- 모임 회원 및 초대 예약석에서 `모임원 또는 초대 상태 = 'INVITED'`이고 초대 만료 일시가 지나지 않은 행 한 건은 한 자리를 예약합니다.
- 초대됨 행은 활성 모임원이 아니므로 모임 상세, 채팅, 회차 및 모임 독후감 접근 권한이 없습니다.
- 일반 가입 가능 좌석은 최대 정원에서 활성 모임원 수와 유효한 예약 초대 수를 뺀 값입니다.
- 즉시 가입과 신청 승인은 일반 가입 가능 좌석만 사용합니다.
- 승인 대기 신청은 좌석을 예약하지 않습니다.
- 초대 수락은 예약 좌석을 활성 모임원 좌석으로 바꾸므로 정원 마감을 이유로 거절하지 않습니다.
- 초대가 거절·취소·만료되면 초대됨 행을 물리 삭제해 예약 좌석을 해제하며 별도 초대 처리 이력을 남기지 않습니다.
- 유효한 초대가 있는 회원의 일반 가입 요청은 초대 수락으로 처리해 별도 좌석을 이중 점유하지 않습니다.
- 유효한 초대가 있는 회원은 같은 모임에 승인 가입 신청을 중복 등록할 수 없습니다.
- 초대 대상 수가 남은 자리보다 많으면 일부 발송하지 않고 전체 발송을 거절합니다.

### 사용자 차단 관계의 공동 모임 예외

이 절은 사용자 차단 기능을 구현한 뒤 적용합니다.

- 차단 전에 이미 같은 모임에 있던 두 사용자는 차단만으로 자동 퇴장시키지 않습니다.
- 차단 당사자와 모두 다른 제3자인 모임장이 두 사용자를 각각 초대한 경우에는 초대와 수락을 허용합니다.
- 차단 당사자 중 한 명이 모임장인 모임에서는 상대의 신규 초대, 즉시 가입, 가입 신청과 승인을 허용하지 않습니다.
- 차단 당사자 사이의 미수락 직접 초대는 차단 시 만료해 예약 좌석을 해제하며 제3자인 모임장이 발송한 유효 초대는 유지합니다.
- 차단 당사자 중 한 명이 모임장인 모임의 처리 중 상대 가입 신청은 차단 시 취소하고 답변을 삭제하며 처리 알림을 생성하지 않습니다.
- 기존 공동 모임에서는 운영에 필요한 닉네임과 본문을 표시하되 차단 상대의 프로필·배경사진은 기본 이미지로 대체하고 공개 프로필 이동을 제공하지 않습니다.
- 차단 상대가 소유한 모임 전용 독후감과 댓글은 읽을 수 있지만 좋아요·댓글·답글을 등록할 수 없습니다.
- 모임 콘텐츠와 반응 권한은 클라이언트가 전달한 모임 여부가 아니라 서버가 확인한 모임·회차 연결과 활성 모임원 자격으로 판정합니다.
- 모임장과 운영자의 퇴장·제재·승계 권한은 개인 차단의 영향을 받지 않습니다.
- 차단 관계와 방향을 별도 상태나 알림으로 제공하지 않지만 제한된 상호작용으로 관계를 추정할 가능성은 보장 범위에서 제외합니다.
- 초대 알림에는 모임장 닉네임과 모임명을 치환하고 모임을 이동 대상으로 저장합니다. 클릭하면 알림번호 공통 경로를 거쳐 내 모임 화면으로 이동합니다.
- 정원을 줄일 때는 활성 모임원과 유효 예약 좌석의 합보다 작게 설정할 수 없습니다.
- 동일 모임·회원의 모임 회원 및 초대 예약석은 현재 관계 한 행만 유지합니다. 탈퇴 또는 퇴장 뒤 재가입·재초대가 허용되면 기존 행을 갱신하고 최신 가입 주기의 일시를 저장하며, 강제 퇴장 이력은 독서모임 강제 퇴장 이력에서만 별도로 보존합니다.

### 강제 퇴장

- 모임장만 다른 활성 모임원을 퇴장시킬 수 있습니다.
- 모임장은 최대 1,000자의 퇴장 사유를 필수로 입력하며, 퇴장 대상·처리자·사유·처리일을 별도 이력으로 보존합니다.
- 퇴장 즉시 대상 회원의 모임 상세, 채팅 및 모임 전용 독후감 접근을 차단합니다.
- 퇴장 대상의 개인 독후감은 본인 소유 기록이므로 자동 삭제하지 않습니다.
- 재가입 제한을 해제해도 강제 퇴장 이력은 삭제하지 않고 해제 일시만 기록합니다.
- 대상자나 처리자 계정이 영구 삭제되면 해당 사용자 연결만 비식별화하고 퇴장 사유와 처리·해제 일시는 유지합니다.
- 모임장은 자신을 퇴장시킬 수 없으며 모임을 물리 삭제하거나 모임장 승계 정책을 따라야 합니다.

### 모임 채팅

- 계정과 모임원 관계가 모두 활성인 회원만 채팅을 조회하고 전송할 수 있습니다.
- 최초 진입과 주기 동기화에서 최신 100건을 조회해 새 메시지와 기존 메시지의 안 읽은 수를 함께 갱신합니다.
- 클라이언트가 생성한 중복 방지 키를 모임 안에서 고유하게 저장해 재전송으로 같은 메시지가 중복 등록되지 않게 합니다.
- 안 읽은 수는 발신자를 제외하고 메시지 등록 당시 이미 가입해 있던 현재 활성 계정·활성 모임원 중 마지막으로 읽은 채팅 번호가 해당 메시지보다 작은 인원으로 계산합니다.
- 메시지 등록 뒤 가입한 회원, 자진 탈퇴·강제 퇴장 회원과 비활성화·영구 탈퇴 대기 계정은 기존 메시지의 안 읽은 수에서 제외합니다.
- 채팅 화면이 보이는 동안 받은 최신 메시지 번호를 회원의 마지막 읽은 위치로 저장하며, 이미 저장한 번호보다 이전으로 되돌리지 않습니다.
- 메시지를 읽으면 해당 모임에서 확인한 메시지까지의 채팅 알림도 모두 읽음 처리합니다. 이후 도착한 메시지와 다른 모임의 알림은 읽음 처리하지 않습니다. 원본 메시지 연결이 없는 과거 알림은 최신 메시지까지 확인하면 정리합니다.
- 해당 모임의 채팅 화면을 보고 있는 회원에게는 새 채팅 알림과 푸시를 생성하지 않습니다. 화면별 열람 신호는 3초 주기로 갱신하고 숨김·이탈 시 해제합니다. 여러 화면 중 하나가 열려 있으면 열람 중으로 판단하며, 비정상 종료 시 마지막 신호 이후 기본 15초 뒤 만료됩니다. 임시 열람 상태는 활동 이력으로 보존하거나 계정 복귀 시 복원하지 않습니다.
- 계정이 다시 활성화되고 활성 모임원 관계가 유지되면 보존한 마지막 읽은 위치를 사용해 이후 메시지의 안 읽은 상태를 이어서 계산합니다. 탈퇴 후 재가입한 회원은 새 가입일 이전 메시지의 안 읽은 수에 포함하지 않습니다.
- 메시지별 사용자 읽음 이력은 별도로 보존하지 않고 회원별 마지막 읽은 위치만 관리합니다.
- 새 메시지는 발신자를 제외한 활성 모임원에게 채팅 알림을 생성하며, 댓글 알림 상황의 공통 아이콘을 사용합니다.
- 채팅 알림은 독서모임 활동 알림과 별도 설정으로 켜고 끕니다. 끈 동안 발생한 알림은 나중에 소급 생성하지 않습니다.
- 비활성화 또는 영구 탈퇴 대기 중에는 채팅 접근·전송·알림을 모두 중지하고, 복귀 시 보존된 채팅 알림 설정을 적용합니다.
- 계정 영구 삭제 시 채팅 본문은 유지하고 작성자 연결만 비식별화하여 `탈퇴한 사용자`로 표시합니다.

### 자진 탈퇴

- 활성 계정의 활성 일반 모임원만 직접 탈퇴할 수 있습니다. 모임장은 모임장 승계 또는 모임 삭제를 먼저 완료해야 하며, 비활성화 또는 영구 탈퇴 대기 계정에는 화면과 API를 제공하지 않습니다.
- 탈퇴 확인 화면에는 도서 추천·투표, 모임장 투표, 모임 회차 참여와 모임원 독후감 연결, 목표 결과 확인 및 가입 신청 등 모든 모임 활동 기록이 삭제된다는 내용을 표시합니다.
- 회차 참여 연결을 삭제해 참여·달성 집계와 모임원 독후감 목록에서 즉시 제외하지만, 회원이 소유한 개인 독후감 원본은 내 독후감 목록에 유지합니다.
- 회원 관계에는 자진 탈퇴 사실과 처리 일시만 남기고 재가입을 차단하지 않습니다. 공개 모임은 기존 가입 방식과 정원 및 승인 정책에 따라 다시 가입할 수 있습니다.
- 계정 비활성화와 영구 탈퇴 대기 전환은 자진 탈퇴를 자동 실행하지 않습니다. 자진 탈퇴 뒤 기존 채팅은 보존하지만 해당 모임의 신규 조회와 전송은 차단합니다.

### 모임 편집과 물리 삭제

- 모임 상세의 더보기 메뉴는 현재 `활성` 모임장에게만 노출하며 `CustomSelect`의 `수정하기`, `삭제하기` 항목으로 제공합니다.
- `수정하기`는 `/reading-clubs/{clubNumb}/edit`로 이동해 기존 생성 폼을 수정 모드로 재사용하고, `PUT /api/reading-clubs/{clubNumb}`로 저장합니다.
- `삭제하기`는 복구 불가 범위와 개인 독후감 보존 내용을 확인 알림으로 안내한 뒤 동의한 경우에만 `DELETE /api/reading-clubs/{clubNumb}`를 호출합니다.
- 모임 편집과 삭제는 화면 버튼 노출뿐 아니라 서버의 모든 수정·삭제 API에서 현재 모임장과 모임 운영 상태를 다시 검증합니다.
- 모임명, 소개 및 카테고리는 운영 중 수정할 수 있으며 카테고리는 유효한 서로 다른 조합 1~3개를 유지합니다.
- 공개 범위는 예정 또는 독서 진행 중 회차가 없을 때만 변경할 수 있습니다.
- 가입 방식은 `대기` 가입 신청이 없을 때만 변경할 수 있습니다. 승인형 질문을 수정해도 제출된 신청은 신청 당시 질문 사본과 답변을 유지하며 새 질문은 이후 신청부터 적용합니다.
- 최대 정원은 2~30명 범위에서 변경할 수 있지만 활성 모임원 수와 만료 전 예약 초대 수의 합보다 작게 줄일 수 없습니다.
- 모임 삭제는 진행 중 회차 유무와 관계없이 허용하며 모임 운영 상태를 종료로 변경하는 종료 처리가 아니라 독서 모임 행을 물리 삭제합니다.
- 독서 모임 삭제와 같은 트랜잭션에서 카테고리, 회원, 초대, 질문, 가입 신청, 회차 참여, 추천, 투표, 모임장 선거, 강제 퇴장·관리자 조치 이력 및 채팅 등 모임 종속 데이터를 외래키 정책에 따라 삭제합니다.
- 회차 참여 연결이 삭제되어도 회원 개인 소유의 독후감과 여러 기능이 공유하는 도서 마스터는 삭제하지 않습니다. 삭제 뒤에는 모임 전용 비공개 독후감 열람 권한과 목표 달성 집계를 복구할 수 없습니다.
- 삭제 확인 화면에는 진행 중 독서를 포함한 모임 데이터가 복구되지 않는다는 점과 개인 독후감은 남는다는 점을 함께 표시합니다.
- 사용자 화면에서는 삭제한 모임을 복구할 수 없으며 관리자도 일반 상태 변경으로 복구하지 않습니다.

### 사이드 메뉴 적용 해석

- 사용자 화면 메뉴에서는 `상위 메뉴 번호 IS NULL`, `메뉴 단계 = 1`인 `독서 모임` 행을 상위 메뉴로 사용하고, 각자 단일 상위 메뉴 번호를 가진 `내 모임`, `모임 찾기` 행이 해당 번호를 상위 메뉴 번호로 참조하는 2단계 메뉴로 구성됩니다.
- `내 모임`은 기존 소유·참여 관계와 받은 초대 및 내 가입 신청을 확인하는 화면이므로 관심분야가 없어도 접근을 허용합니다.
- `모임 찾기`는 공개 모임 추천·탐색 화면이므로 관심분야를 하나 이상 저장해야 진입할 수 있습니다.
- 가입하지 않은 공개 모임 상세의 직접 접근도 `모임 찾기` 흐름으로 처리하고 같은 관심분야 필수 조건을 적용합니다.
- 현재 사용자 메뉴 API와 드로어는 평면 목록만 지원하므로 사용자 화면 메뉴 행 추가만으로 2뎁스가 완성되지 않습니다.
- 메뉴는 연결 라우트와 2뎁스 렌더링이 배포된 뒤 노출해야 합니다.

### 공통 신고·차단 후속 출시

- 1차 독서 모임 출시에는 인앱 신고 접수, 신고 심사 화면 및 사용자 차단 기능을 포함하지 않습니다.
- 신고 대상은 독서 모임에 종속시키지 않고 독후감, 댓글, 모임, 사용자, 채팅 메시지와 향후 추가 대상을 수용하는 공통 대상 유형으로 설계합니다.
- 신고와 차단은 서로 다른 기능으로 관리합니다. 신고는 운영자 심사와 제재를 요청하는 절차이고, 차단은 차단한 회원의 화면과 상호작용 범위를 제한하는 개인 설정입니다.
- 후속 설계에서는 대상 유형별 신고 가능 조건, 중복 신고 기준, 증거 스냅샷, 처리 상태, 관리자 열람 범위, 제재 연계, 이의 제기 및 보존·삭제 정책을 별도로 확정해야 합니다.
- 공통 신고 테이블명은 기존 독후감 테이블 독후감과 혼동되지 않도록 별도 명칭을 사용해야 합니다.
- 후속 기능이 출시되기 전의 분쟁과 위반 제보는 기존 고객 문의 및 관리자 운영 절차로 처리하며, 1차 화면에 구현되지 않은 신고 버튼을 노출하지 않습니다.

- `POST /api/reading-clubs/history/{clubNumb}`는 `활성` 계정인 현재 모임장만 호출할 수 있습니다. 같은 모임의 예정·진행 회차가 있으면 새 회차를 만들지 않으며, 요청별 회차 멱등키로 네트워크 재시도의 중복 생성을 막습니다.
- 등록 시점에 계정 상태와 모임원 상태가 모두 `활성`인 모임장과 모임원을 참여자로 확정합니다. 회차, 각 참여자의 `읽는 중` 상태 독후감, 독서 모임 회차 참여 연결은 하나의 트랜잭션에서 생성하며 도서와 독서 시작일, 독서 종료일 또는 목표 종료일은 모두 동일하게 기록합니다.

### 공통 투표 데이터

- 다음 도서 선정은 선정 도서와 도서 추천을, 모임장 선거는 선거 데이터를 업무 원본으로 각각 유지합니다. 모임장 변경 전후는 선거의 기존 모임장과 당선자 정보로 확인하며 별도 변경 이력은 두지 않습니다.
- 모임 투표의 투표 유형이 `BOOK`이면 선정 도서 번호, 모임장이면 선거 번호를 연결하며 두 업무 번호를 동시에 저장하지 않습니다.
- 모임 투표 선택지의 대상 번호는 `BOOK` 투표에서 도서 마스터의 도서 번호, 모임장 투표에서 후보 회원의 사용자 계정과 프로필의 사용자 번호입니다. 부모 투표 유형이 대상 의미를 결정하므로 선택지에 별도 대상 유형, 도서 번호, 후보 사용자 및 투표 선택지 번호를 두지 않습니다.
- 같은 책이 여러 회원에게 추천되어도 도서 선택지는 도서 번호 기준 한 건만 생성하고 추천자와 추천 문구는 도서 추천에 각각 유지합니다.
- 모임장 후보가 본인 등록에 동의하면 후보 사용자 번호로 선택지를 생성하고 철회·퇴장·정지 등으로 자격을 잃으면 선택지 상태를 변경합니다.
- 대상 번호는 투표 유형에 따라 서로 다른 마스터를 가리키므로 도서 또는 회원 마스터에 단일 물리 FK를 연결하지 않습니다. 선택지 생성 시 업무 원본과 대상 존재 여부를 검증하고 처리 대상 표시명에 당시 도서명 또는 닉네임을 보존합니다.
- 모임 투표 자격은 `(모임 번호, 투표 번호, 사용자 번호)`를 기본키로 사용하고, 선택한 `(모임 번호, 투표 번호, 대상 번호)`가 같은 투표의 모임 투표 선택지에 존재하도록 복합 FK를 둡니다.
- 마감 전 투표 변경은 모임 투표 자격 새 행을 추가하지 않고 같은 유권자 행의 대상 번호를 갱신합니다.
- 결선은 새로운 투표 번호를 발급하고 결선 투표의 이전 투표 번호로 본선을 연결하며 동률인 대상만 새 투표 선택지로 등록합니다.

### 복합키와 모임별 번호

- 모임 번호는 전역 `AUTO_INCREMENT` 단일 기본키로 유지합니다.
- 채팅을 제외한 모임 종속 테이블의 기본키와 부모 참조 외래키는 모임 번호로 시작합니다. 예를 들어 회차는 `(모임 번호, 모임별 회차 번호)`, 회차 참여자는 `(모임 번호, 모임별 회차 번호, 모임 회차별 참여 번호)`, 선거는 `(모임 번호, 선거 번호)`를 사용합니다.
- 독서 모임 회차 참여는 영구 탈퇴 뒤에도 참여 수와 목표 달성 집계를 비식별 상태로 보존해야 하므로 사용자 번호를 기본키에서 제외하고 Null을 허용합니다. 활성 식별값이 있는 동안에는 `(모임 번호, 모임별 회차 번호, 사용자 번호)` 고유 제약으로 회원별 한 행을 보장하고 독후감 번호에도 고유 제약을 둡니다.
- 모임 카테고리, 회원, 가입 질문처럼 관계 자체로 유일성이 결정되는 테이블에는 불필요한 순번을 추가하지 않습니다.
- 번호가 필요한 자식 데이터는 모임 안에서만 유일한 지역 번호를 사용합니다. 다른 모임에서 같은 번호가 존재할 수 있으므로 API, Mapper, Service 및 로그에서는 항상 모임 번호와 지역 번호를 함께 전달합니다.
- 공통 투표는 `(모임 번호, 투표 번호)`, 투표 선택지는 `(모임 번호, 투표 번호, 대상 번호)`, 유권자 명부와 투표용지는 각각 `(모임 번호, 투표 번호, 사용자 번호)`를 사용합니다.
- 투표 번호는 같은 모임 범위의 `MAX(투표 번호) + 1`로 발급하지만 대상 번호가 선택지 식별자이므로 별도 선택지 순번은 발급하지 않습니다.
- 지역 번호는 각 대상 테이블의 `INSERT ... SELECT` 문 안에서 동일 모임 번호의 `COALESCE(MAX(지역 번호), 0) + 1`로 계산합니다. 번호 조회와 등록을 별도 SQL로 나누지 않습니다.
- 같은 모임에서 같은 종류의 등록이 정확히 동시에 실행되어 중복키가 발생하면 기본키 또는 고유 제약으로 저장을 거절하고 트랜잭션을 롤백합니다. 이 가능성은 채팅 외 기능의 낮은 동시 쓰기 빈도를 수용하는 단순화의 잔여 위험으로 봅니다.
- 물리 삭제된 행이 최대 번호였다면 해당 번호가 다시 발급될 수 있으므로 지역 번호는 영구 불변 업무 번호로 사용하지 않습니다. 장기 감사 추적이 필요한 이력 행은 물리 삭제하지 않습니다.
- 채팅은 메시지 양과 동시 쓰기를 고려해 예외로 둡니다. 모임 채팅의 채팅 메시지 번호는 전역 `AUTO_INCREMENT` 단일 기본키이고 모임별 조회는 `(모임 번호, 채팅 메시지 번호)` 인덱스를 사용합니다. 번호만으로 접근을 허용하지 않고 모임 번호와 활성 모임원 자격을 함께 검증합니다.

#### 정책 결정 모임장 부재 확정과 선거

정책 결정에서 부재는 단순히 최근 로그인이나 모임 활동이 없다는 뜻이 아니라 모임장 권한을 행사할 수 없거나, 스스로 권한 이전을 요청했거나, 모임장에게만 부여된 다음 도서 확정 책임을 14일 동안 이행하지 않은 것으로 확정된 상태를 의미합니다. 부재 사유가 확정되면 관리자나 시스템이 후임을 지정하지 않고 활성 모임원 선거를 시작합니다.

| 상황 | 부재 판정 | 확정 처리 |
| --- | --- | --- |

14일 기산점은 이전 회차 종료일이나 추천 시작일이 아니라 시스템이 모임장 전용 다음 도서 확정 상태를 시작한 일시입니다. 모임원 추천·투표가 진행 중이거나 모임이 일시 중지인 기간에는 이 상태를 시작하지 않습니다. 시작 즉시 모임장에게 기한을 알리고 14일이 되는 시각까지 유효한 다음 도서가 확정되면 지연 사유를 생성하지 않습니다. 도서 확정과 기한 판정이 경합하면 같은 모임 또는 도서 선정 행을 잠그고 먼저 확정된 처리만 인정합니다. 부재 사유와 선거가 확정된 뒤에는 기존 모임장의 뒤늦은 도서 확정으로 선거를 자동 취소하지 않습니다.

선거 시작 시 확정 부재 사유, 근거, 확정자와 일시를 모임장 선거 원본에 기록합니다. 도서 미확정 사유에는 책임 시작 일시, 14일 마감 일시 및 판정 당시 도서 선정 상태를 함께 기록합니다. 선거가 끝날 때 당선자의 활성 모임원 자격을 다시 확인하고 모임장과 회원 역할을 한 트랜잭션에서 변경합니다. 선거 중 새 가입·초대·신청 승인, 회차 확정 및 모임장 전용 설정 변경은 중지하고 기존 모임원의 조회·채팅·후보 등록·투표는 유지합니다. 유권자는 시작 시 고정하고, 본인이 동의한 활성 모임원만 후보가 되며, 24시간 동안 정족수 없이 비밀투표를 진행합니다. 유효표 최다 득표자가 당선되고 동률이면 동률 후보만 24시간 결선 투표를 한 번 진행합니다. 후보나 유효표가 없으면 24시간을 한 번 연장한 뒤에도 성립하지 않을 때 모임을 일시 중지로 전환합니다.

## 정상 흐름 정책

1. 회원은 웰컴 화면에서 관심분야를 선택하거나 건너뛰고 서비스 이용을 시작합니다.
2. 관심분야가 없는 회원은 `내 모임`, 받은 초대, 내 가입 신청 및 가입한 모임 상세를 계속 이용할 수 있지만, `모임 찾기`와 미가입 공개 모임 상세에는 진입할 수 없습니다. 관심분야를 하나 이상 저장하면 공개 모임 목록을 조회하고 `모임 찾기`에서 현재 관심분야를 수정할 수 있습니다. 공개 모임 검색 결과에서는 로그인 사용자가 만든 모임을 제외합니다.
3. 공개 여부와 관계없이 모임장은 맞팔 회원을 초대할 수 있으며, 초대 발송과 동시에 3일 동안 좌석을 예약합니다.
4. 모임장이 회차의 도서와 목표 기간을 확정하면 그 시점의 모든 활성 모임원이 자동 참여하며 각 회원의 개인 독후감이 `읽는 중`로 생성되어 독서 모임 회차 참여의 독후감 번호로 연결됩니다.
5. 참여자는 개인 또는 모임 화면에서 실제 독서 기간과 독후감을 작성하며 모든 값은 독후감에 저장됩니다.
6. 목표 종료 시각까지 `완독`인 참여자만 목표 달성자로 고정합니다. 목표 기간 안에 활성 참여자 전원이 `완독`이면 활성 모임장이 확인 후 조기 마감할 수 있으며, 회차에는 전체 참여 인원과 달성 인원·달성자만 표시합니다. 미달성자의 개인 독후감은 `읽는 중`로 계속 유지합니다.
7. 진행 중인 회차부터 권한이 있는 활성 모임원에게 다른 활성 모임원이 `완독`으로 작성한 독후감을 공개 여부와 관계없이 제공하고, 모임 상세와 목표 결과의 모임원 독후감 목록에서 작성자별 독후감 일부를 확인한 뒤 상세 화면으로 이동할 수 있게 합니다. 비활성화·영구 탈퇴 대기 계정과 비활성 모임원의 독후감은 편수와 목록에서 제외합니다.
8. 다음 도서 투표는 상시 진행합니다. 활성 모임원은 투표 주기마다 한 권만 후보로 등록하고 한 번만 투표할 수 있으며, 완료한 투표는 변경할 수 없습니다.
9. 독서 회차가 시작되면 해당 회차 목표 종료일 이틀 뒤를 투표 마감일로 정합니다. 후보 등록과 본인 후보 삭제는 마감일 하루 전까지만 허용하고 마감일에는 잠그며, 투표는 마감일까지 허용합니다. 마감일 다음날부터 이전 후보와 투표를 제외한 새 주기를 시작합니다.
10. 모임장의 확정 부재 사유가 발생하면 모임장 선거를 열고 활성 모임원의 투표 결과에 따라 다음 모임장으로 권한을 원자적으로 이전합니다.

## 예외와 실패 처리 정책

- 관심분야를 선택하지 않거나 저장에 실패해도 웰컴 완료 조건을 충족하면 `온보딩 완료 여부 = 'Y'`로 처리하고 관심분야 저장 실패만 안내합니다.
- `모임 찾기`에서 관심분야 저장에 실패하거나 한 건도 선택하지 않으면 선택 화면에 머물며 공개 모임 목록과 미가입 공개 모임 상세를 조회하지 않습니다.
- 회원의 관련 업무 데이터 항목 하위 관심분야 분류값이 활성 공지사항 카테고리 분류 대분류의 활성 하위 코드가 아니면 관심분야 교체 저장 전체를 실패 처리하고 기존 선택값을 유지합니다.
- 모임 카테고리가 1개 미만이거나 3개를 초과하거나, 중복 코드·중복 정렬 순서·유효하지 않은 관련 업무 데이터 항목 하위 관심분야 분류값을 포함하면 모임 생성 또는 카테고리 수정을 저장하지 않습니다.
- 카테고리 수정 요청은 모든 조합을 먼저 검증한 뒤 모임 행을 잠그고 독서 모임 카테고리를 한 트랜잭션에서 교체합니다. 일부 조합만 반영하는 상태는 허용하지 않습니다.
- 회원 관심분야나 모임이 참조하는 대분류 및 관심분야 분류값은 삭제하거나 다른 의미로 변경할 수 없습니다. 신규 선택만 막으려면 사용 여부를 비활성화합니다.
- 공개 모임 정원이 승인 직전에 마감되면 신청은 승인하지 않고 신청자와 모임장에게 안내합니다.
- 가입 신청 승인·거절 시 신청 답변 삭제까지 같은 트랜잭션에서 완료하지 못하면 처리 상태를 변경하지 않습니다.
- 유효한 초대가 예약한 좌석은 즉시 가입과 신청 승인에서 사용할 수 없습니다.
- 유효한 초대 수락은 정원 마감을 이유로 실패 처리하지 않고 예약 좌석을 활성 모임원 좌석으로 전환합니다.
- 같은 가입·승인 요청이 재전송되어도 회원 행을 중복 생성하지 않습니다.
- 다음 도서 후보 등록과 투표는 활성 모임원 행을 잠근 뒤 현재 주기의 기존 등록 여부를 확인하여 동시 요청에도 1인 1후보와 1인 1투표를 보장합니다. 이미 투표한 사용자의 다른 후보 투표 요청과 마감일의 후보 등록·삭제 요청은 전체 거절합니다.
- `MAX + 1` 등록에서 기본키 충돌이 발생하면 해당 업무 트랜잭션을 롤백하고 요청을 재시도할 수 있게 합니다. 충돌한 번호를 다른 값으로 임의 보정해 일부 데이터만 저장하지 않습니다.
- 미등록 도서 확보에 실패하면 회차와 일부 참여자 독후감을 남기지 않습니다.
- 참여자 독후감 일괄 생성 중 한 건이라도 실패하면 전체 회차 확정을 롤백합니다.
- 현재 독서의 도서 변경 가능 여부를 판단할 때 연결 독후감 행을 잠그며, 작성된 독후감이 있으면 서버가 도서 변경 요청을 거절합니다. 기간만 변경한 요청은 허용하고 회차와 연결 독후감 중 하나라도 갱신에 실패하면 전체 수정을 롤백합니다.
- 목표 종료 전에도 `완독`으로 작성한 활성 모임원의 독후감 본문·평점은 같은 모임의 활성 모임원에게 반환합니다. `읽는 중` 또는 중단 상태의 독후감과 비활성화·영구 탈퇴 대기 계정 및 비활성 모임원의 독후감은 편수와 목록에서 제외합니다. 회차 목표 요약은 전체 참여 인원과 현재 달성 인원·달성자만 제공하고 미달성자 명단은 제공하지 않습니다.
- 퇴장 처리와 권한 회수 중 일부가 실패하면 회원 상태 변경을 확정하지 않고 재시도할 수 있게 합니다.
- 채팅 연결이 끊겨도 작성 중인 입력을 보존하고 이전 메시지는 REST로 다시 조회합니다.
- 한 모임에서 진행 중인 모임장 선거는 하나만 허용합니다. 같은 유권자의 재투표는 마감 전후와 관계없이 거절하고 최초 투표만 집계합니다.
- 모임장 선거 마감과 권한 이전이 일부만 반영되지 않도록 모임장 선거와 모임 투표 잠금, 당선자 자격 재검증 및 역할 변경을 한 트랜잭션으로 처리합니다.

## 복구와 취소 정책

- 가입 신청자는 승인 전 신청을 취소할 수 있고 취소와 동시에 답변을 삭제합니다.
- 공개·비공개 맞팔 초대는 수락 전 모임장이 취소할 수 있습니다.
- 모임장의 멤버·가입 관리 화면은 활성 회원에게 보낸 만료 전 초대를 조회하며, 각 초대에 취소 기능을 제공합니다. 비활성화 또는 삭제 대기 대상은 정책 결정에 따라 조회와 취소 대상에서 제외합니다.
- 초대 거절·취소·만료 시 예약 좌석을 즉시 일반 가입 가능 좌석으로 반환합니다.
- 현재 회차의 연결 독후감이 모두 자동 생성 초기 상태이면 도서와 기간을 수정할 수 있고, 하나라도 작성된 뒤에는 기간만 수정할 수 있습니다. 참여 명단은 별도로 편집하지 않고 회차 생성 시점의 활성 모임원으로 자동 구성합니다.
- 회차 확정 후 취소 시 작성 내용이 없는 자동 생성 독후감은 삭제하고 내용이 있으면 회차 연결만 해제해 개인 기록으로 유지합니다.
- 강제 퇴장은 단순 실행 취소로 되돌리지 않고 모임장이 재가입 차단을 해제한 뒤 새 가입 절차를 거칩니다.
- 공개된 독후감의 수정은 같은 원본을 사용하는 모임 화면에 즉시 반영하며 1차 출시에는 별도 수정 이력을 만들지 않습니다.

## 모임원 프로필 목록 노출 정책

- 모임원 프로필 목록은 해당 모임의 `활성` 회원과 공개 중인 활성 모임을 조회하는 비회원이 조회할 수 있습니다. 비공개 또는 운영 중이 아닌 모임은 활성 모임원에게만 제공합니다.
- 목록에는 `사용자 계정 상태 = '활성'`, `모임 회원 및 초대 예약석의 모임원 또는 초대 상태 = '활성'`를 모두 만족하는 회원만 포함합니다.
- 프로필 이미지는 사용자 계정과 프로필의 프로필 이미지 파일 번호로 업로드 파일 정보를 조회하며, 이미지가 없거나 로드에 실패하면 `/img/common/icon-user.svg`를 표시합니다.
- 목록은 모임장을 먼저 표시하고 이후 가입 일시와 사용자 번호 순서로 표시합니다.
- 계정이 `비활성화` 또는 영구 탈퇴 대기로 전환되면 기존 모임 관계는 유지하지만 계정 상태 조건으로 목록에서 제외합니다.
- 계정 비활성화 복귀 또는 영구 탈퇴 취소로 `활성` 상태가 되면 유지된 모임원 자격에 따라 목록에 다시 표시합니다. 물리 삭제된 계정과 모임 관계는 복구하지 않습니다.

## 미가입 공개 모임 독서 정보 노출 정책

- 공개 중인 활성 모임의 상세에서는 비회원에게 현재 독서 상태·도서·목표 기간·활성 참여자 기준 목표 달성 집계와 활성 모임원 목록을 제공합니다.
- 비회원은 이전 독서 기록에서 완료 회차의 도서·목표 기간·활성 참여자 기준 참여 수와 달성 수를 확인할 수 있습니다.

- 비활성화 또는 영구 탈퇴 대기 계정과 비활성 모임원은 현재·과거 참여 수, 달성 수와 모임원 목록에서 제외합니다.

### 구현 상태와 잔여 항목

- 단일 공지사항 카테고리 분류 관심분야 계층과 독서 모임 공통코드는 `승인된 비공개 기준정보 패키지` 초기 데이터에 유지합니다.
- 공통코드 세부 항목의 상위 분류값과 회원 독서 관심분야, 독서 모임, 독서 모임 카테고리, 모임 회원 및 초대 예약석, 모임 가입 질문, 승인형 모임 가입 신청, 독서 모임 회차, 독서 모임 회차 참여를 생성 DDL에 유지하며 공통코드 그룹의 정렬 순서는 사용하지 않습니다.
- 최초 로그인 관심분야 조회·저장 API와 웰컴 화면 선택 UI만 유지합니다. 관심분야 저장 실패나 건너뛰기는 `온보딩 완료 여부 = 'Y'` 완료 처리를 막지 않습니다.
- 공개 모임 탐색·생성·가입과 모임장용 초대·가입 승인·활성 일반 멤버 강제 퇴장, 일반 모임원 자진 탈퇴, 신청자용 승인 전 가입 신청 취소, 회차·독후감 연결 API 및 `/reading-clubs` 화면을 구현했습니다. 강제 퇴장은 멤버 상태를 퇴장으로 변경하고 재가입을 차단한 뒤 대상 알림까지 같은 트랜잭션으로 처리합니다. 자진 탈퇴는 재가입을 차단하지 않고 모임 활동 연결을 삭제하되 개인 독후감 원본을 보존합니다. 가입 신청 취소는 본인의 처리 대기 신청 행을 삭제해 답변을 즉시 제거합니다. 회차 등록은 독서 모임 회차, 독후감, 독서 모임 회차 참여를 같은 트랜잭션에서 생성하며, 현재 독서 수정은 작성된 연결 독후감이 있으면 도서 변경을 차단하고 기간 변경을 연결 독후감에 동기화합니다. 종료 회차는 목표 결과와 회차 독후감 및 가입 이전을 포함한 이전 독서 기록 목록으로 조회할 수 있고, 공개 중인 활성 모임의 비회원에게는 현재·과거 독서 요약과 활성 모임원 목록만 제공합니다.
- 관리자 독서 모임 조회·상태 조치 화면은 아직 구현하지 않았습니다.
- 모임 채팅 조회·전송, 알림 설정, 메시지별 안 읽은 인원 수와 회원별 마지막 읽은 위치 갱신을 구현했습니다. 안 읽은 수는 현재 활성 계정·활성 모임원과 가입 시점을 기준으로 계산하며 별도 메시지별 읽음 이력은 저장하지 않습니다.
- 독후감, 댓글, 모임, 사용자 및 채팅 메시지를 포괄하는 공통 신고·차단 데이터와 화면 및 이 문서의 사용자 차단 공동 모임 예외는 후속 출시 범위이며 아직 구현하지 않았습니다.
